# 온톨로지 스키마 — 「잘 자는 법」 수면 Q&A

이 문서만 읽고도 규격에 맞는 새 노드를 작성할 수 있어야 한다. `index.md`는 빌드 산출물이므로 손대지 않는다(노드가 단일 진실원천).

---

## 1. 노드 클래스 (type) — 4종

| type | 의미 | 예 |
|---|---|---|
| `생리기전` | 몸 안에서 일어나는 작용·물질 | 멜라토닌, 세로토닌, 수면압력, 심부체온, REM수면 |
| `실천행동` | 사용자가 실행하는 행동·습관 | 아침_산책, 청색광차단, 족욕, 미온수_샤워 |
| `영향요인` | 잠에 영향을 주는 외부·섭취 요인 | 카페인, 알코올, 온습도, 저녁식사_시간 |
| `생애단계` | 연령대별 수면 변화 | 아동기_수면, 노년기_수면 |

---

## 2. 노드 id 명명 규칙 (C1) — HARD

- id = **한글 snake_case**. 띄어쓰기는 `_`로 연결한다. 예: `아침_산책`, `저녁식사_시간`.
- **파일명 = id**. `nodes/멜라토닌.md`의 frontmatter `id`는 반드시 `멜라토닌`.
- 허용 문자 정규식: `^[가-힣A-Za-z0-9_]+$` (한글·영문·숫자·언더스코어만). REM·NREM 같은 영문 약어는 `REM수면`처럼 한글과 결합 가능.
- 관계 타깃과 sources의 노드 참조도 모두 이 규칙을 따른다.
- 빌드 검증: id 정규식 위반 또는 파일명≠id이면 빌드 실패.

---

## 3. 닫힌 관계 어휘 (C2) — 능동 8종만 허용, HARD

관계는 노드에 **한 방향(능동)만** 적는다. 역관계는 빌드가 자동 생성한다. 아래 8종 외 술어는 빌드 실패.

| 술어 | 방향 의미 (주체 = 이 노드) | 예 (`세로토닌` 노드 기준) |
|---|---|---|
| `증가시킨다` | 주체가 대상을 증가/촉진 | — |
| `감소시킨다` | 주체가 대상을 감소/억제 | — |
| `원료가_된다` | 주체가 대상의 원료/전구체 | `[원료가_된다, 멜라토닌]` |
| `선행한다` | 주체가 대상보다 시간상 먼저 | `[선행한다, 멜라토닌_분비]` |
| `권장한다` | 주체(행동)가 대상을 권장 | `[권장한다, 청색광차단]` |
| `주의한다` | 주체가 대상을 주의/제한 | `[주의한다, 카페인]` |
| `측정지표` | 주체의 상태를 재는 지표 | `[측정지표, 심부체온]` |
| `반례` | 주체의 통념에 대한 반례/예외 | `[반례, 멜라토닌_보충제]` |

**방향 규칙(중요):** "아침 산책이 세로토닌을 늘린다"는 사실은 **원인 노드(`아침_산책`)** 에 `[증가시킨다, 세로토닌]`으로 적는다. 즉 *주체가 대상에게 작용*하는 방향으로 한 번만 기록한다. 같은 사실을 `세로토닌` 노드에 수동으로 다시 적지 않는다(중복 금지).

### 역술어 매핑표 (빌드가 index 역관계 표시에 사용)

| 정방향 | 역방향(표시 라벨) |
|---|---|
| 증가시킨다 | ←증가됨 |
| 감소시킨다 | ←감소됨 |
| 원료가_된다 | ←원료를_가짐 |
| 선행한다 | ←후행함 |
| 권장한다 | ←권장됨 |
| 주의한다 | ←주의대상 |
| 측정지표 | ←측정대상 |
| 반례 | ←반례대상 |

> `_by` 류 수동 술어는 **폐지**. 능동/수동 두 방식으로 같은 사실을 적을 수 있는 여지를 없애 drift를 차단한다.

## 4. evidence 등급 — 3종

| 등급 | 의미 |
|---|---|
| `일반원칙` | 책이 일반 통념·과학 상식으로 제시 |
| `저자_개인경험` | 저자(김성호 등) 개인 체험·취향 (예: 미지근한 토마토 한 입) |
| `논쟁중` | 책이 효과를 단정하지 않거나 견해가 갈리는 것 (예: 멜라토닌 보충제) |

---

## 5. sources 인용 포맷 (C3)

- 본문 인용: `"파일코드 §장-절"` 형식. 파일코드는 `260608`(정본) 또는 `260528`(보강). 예: `"260608 §6-1"`.
- 인용 문헌: 자유 서술. 예: `"아리타 히데호 『세로토닌 뇌 활성법』"`, `"니시노 세이지"`, `"『3분 수면 혁명』"`.
- 한 노드에 본문 인용 ≥1개 권장(S1 커버리지에 집계됨).

## 6. 노드 frontmatter 스키마

```yaml
---
id: <한글 snake_case, 파일명과 동일>
type: 생리기전 | 실천행동 | 영향요인 | 생애단계
aliases: ["구어체1", "동의어2"]        # 라우팅용. 다른 노드와 중복 금지
summary: "인덱스에 들어갈 한 줄 요약"   # 한 문장
relations:                            # 선택. 닫힌 어휘 8종, [술어, 타깃id]
  - [증가시킨다, 멜라토닌]
sources: ["260608 §2-2"]              # 1개 이상 권장
evidence: 일반원칙 | 저자_개인경험 | 논쟁중
---
본문 1~3문장. 노드가 설명하는 핵심 내용.
```

### 필드 규칙
- `id`, `type`, `summary`, `evidence`: 필수.
- `aliases`: 권장(라우팅 핵심). 비우면 id만으로 매칭.
- `relations`: 선택. 비어도 됨. 있으면 술어는 8종 한정, 타깃은 존재하는 노드 id.
- `sources`: 권장. 본문 노드는 `"파일코드 §장-절"` 1개 이상.

---

## 7. 검증 게이트 요약 (build_index.py가 강제)

빌드 실패(종료코드≠0) 조건:
1. 관계 술어가 8종 닫힌 어휘에 없음.
2. 관계 타깃이 존재하지 않는 노드 id.
3. `evidence`가 3종 등급에 없거나 누락.
4. `aliases`가 다른 노드와 중복.
5. `id` 정규식 위반 또는 파일명≠id.

경고(설정에 따라 실패): S1 커버리지에서 인용 0인 절 존재.
