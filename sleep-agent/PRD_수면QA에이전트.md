## 0. 한 줄 요약 (구현자에게)

「잘 자는 법」 원고를 **노드 마크다운이 단일 진실원천**인 온톨로지로 변환하고, 빌드 스크립트가 **인덱스·역관계·검증**을 자동 생성한다. 이를 **공식 `telegram@claude-plugins-official` Channels 플러그인**으로 단체 텔레그램방에 붙여, 인덱스로 라우팅→노드 근거로 답하고 사용자별 프로필로 개인화하는 상시 Claude Code 세션을 만든다. **Anthropic API 키 없이 claude.ai Pro/Max 구독 인증으로만 동작**해야 한다.

## 1. 배경 · 목표 · 비목표

**배경.** 소스는 업로드된 2개 파일. `잘자는법_260608.md`(1008줄, **정본**), `잘자는법_260528.md`(781줄, 보강 참조). 두 파일 모두 마크다운 헤딩(`#`)이 없고 절 제목이 볼드 텍스트(`**2-1. …**`)로 되어 있음에 유의(파싱 시 §C3). 목차: 1 개인 이야기 / 2 수면 원리(리듬·멜라토닌·수면압력) / 3 과정(이완·NREM·REM) / 4 생애주기 / 5 도움 요소(잠들기 전 준비·호르몬·먹을것·마실것) / 6 환경(온습도·체압·공간) / 7 소도구(베개·매트리스) / 8 부작용 / 9 마무리.

**목표.**
- G1. 책 내용을 출처·근거등급이 붙은 온톨로지로 무손실 구조화한다.
- G2. 단체방 @멘션/호출어에 3~5문장으로 빠르고 정확히 답한다.
- G3. 모든 답변이 노드에 근거하고, 책에 없으면 추측하지 않는다.
- G4. 사용자별 프로필로 개인 맥락에 맞는 답을 준다(Hermes 패턴).
- G5. 온톨로지를 반복 업데이트해도 인덱스·역관계가 자동으로 일관되게 유지된다.

**비목표.** 의료 진단·약물·복용량 조언(가드레일 차단), 임베딩/벡터DB(소규모라 과투자), 웹 검색 답변(소스=책 한정), 커스텀 브리지 코드(공식 플러그인만).

## 2. 핵심 아키텍처 결정 (grill 합의)

**D1 — 검색은 2-tier.** 온톨로지 전체는 컨텍스트에 들어갈 크기(노드 60~100개 ≈ 15~30K 토큰)지만, 매 그룹 메시지마다 전량 로드하면 구독 rate limit을 갉아먹는다. 따라서:
- **Tier 1 (상주):** `index.md` — 노드 id + **별칭/동의어** + 한 줄 요약 (≈3~5K 토큰). 세션 내내 컨텍스트에 두고 구어체 질문("잠이 안 와")을 정본 노드("입면", "수면압력")로 라우팅. **상주 방식은 §C4(CLAUDE.md `@import`)로 구현.**
- **Tier 2 (온디맨드):** `nodes/*.md` — 인덱스로 매칭된 2~3개 노드만 read.

**D2 — 노드가 단일 진실원천, 인덱스는 파생.** `index.md`는 **절대 손으로 편집하지 않는다.** `scripts/build_index.py`가 모든 노드 frontmatter를 읽어 재생성한다. 이로써:
- **drift 불가능** — 두 군데를 고칠 일이 없다.
- **역관계 자동 생성** — 노드엔 관계를 한 방향만 적고, 빌드가 인덱스에 역링크를 채운다(역술어 매핑은 schema.md, §C2).
- **검증 게이트** — 빌드 시 ① 닫힌 관계 어휘 위반 ② 존재하지 않는 id로의 관계(깨진 참조) ③ evidence 등급 누락 ④ 별칭 중복 ⑤ id 명명 규칙 위반을 잡아 **빌드를 실패시킨다.**

업데이트 루프 = `nodes/ 편집 → build_index.py 실행 → 검증 통과 시 index.md 갱신 → git commit`.

## 4. 데이터 규격

**노드 id 규칙(C1).** id = **한글 snake_case**(공백→`_`), 파일명과 동일(`멜라토닌.md`의 id는 `멜라토닌`). 관계 타깃·sources 참조 모두 동일 규칙을 따른다. 별칭(aliases)은 자유 구어체. 검증 게이트가 id 정규식(`^[가-힣A-Za-z0-9_]+$`)과 파일명 일치를 확인한다.

**노드** (`ontology/nodes/세로토닌.md`) — 사람/에이전트가 편집하는 유일한 곳:
```yaml
---
id: 세로토닌
type: 생리기전                # 생리기전 | 실천행동 | 영향요인 | 생애단계
aliases: ["세로토닌", "행복호르몬"]   # 구어체·동의어 → 라우팅 핵심
summary: "낮의 햇빛·운동으로 분비되어 밤 멜라토닌의 원료가 되는 신경전달물질"  # 인덱스에 들어갈 한 줄
relations:                    # 한 방향만 적는다. 역관계는 빌드가 생성. (술어는 schema의 닫힌 8종만)
  - [원료가_된다, 멜라토닌]
  - [증가시킨다, 아침_산책]    # 능동 한 방향만 — schema 방향 규칙 따름
  - [증가시킨다, 햇빛]
sources: ["260608 §6-1", "아리타 히데호 『세로토닌 뇌 활성법』"]   # 본문 인용은 "파일코드 §장-절"
evidence: 일반원칙            # 일반원칙 | 저자_개인경험 | 논쟁중
---
세로토닌은 낮 동안 햇빛·리듬운동으로 분비되고 밤에 멜라토닌의 원료가 된다. 낮을 잘 보내는 것이 잠에 중요한 이유다.
```
> 주의(C1): 관계 타깃 `아침_산책`·`햇빛`·`멜라토닌`도 각각 노드로 존재해야 한다(없으면 빌드 실패).

**index.md** (빌드 산출물, 형식 예시 — 구현자가 build 스크립트로 생성):
```
# Ontology Index (AUTO-GENERATED by build_index.py — DO NOT EDIT)
## 세로토닌 [생리기전]
별칭: 세로토닌, 행복호르몬
요약: 낮의 햇빛·운동으로 분비되어 밤 멜라토닌의 원료가 되는 신경전달물질
관계: 원료가_된다→멜라토닌 · 증가시킨다→아침_산책,햇빛
역관계: 멜라토닌←(원료가_된다) · 아침_산책←(증가시킨다)
근거: 260608 §6-1 / 일반원칙
```

**프로필** (`profiles/<telegram_user_id>.md`):
```yaml
---
user_id: "412587349"

tried: [{ 방법: "족욕", 효과: "보통" }]
```

---

## 5. 작업 분해 (Claude Code 실행 순서)

### Task 1 — schema.md 작성
- 클래스 4종(`생리기전 | 실천행동 | 영향요인 | 생애단계`).
- **id 명명 규칙(C1)**: 한글 snake_case, 파일명=id, 정규식 `^[가-힣A-Za-z0-9_]+$`.
- **닫힌 관계 어휘 8종(C2)** — 능동만 허용, `_by` 계열 폐지:
  `증가시킨다 · 감소시킨다 · 원료가_된다 · 선행한다 · 권장한다 · 주의한다 · 측정지표 · 반례`.
- **역술어 매핑표(C2)** — 빌드가 인덱스 역관계 생성 시 사용:
  | 정방향 | 역방향(표시용) |
  |---|---|
  | 증가시킨다 | ←증가됨 |
  | 감소시킨다 | ←감소됨 |
  | 원료가_된다 | ←원료를_가짐 |
  | 선행한다 | ←후행함 |
  | 권장한다 | ←권장됨 |
  | 주의한다 | ←주의대상 |
  | 측정지표 | ←측정대상 |
  | 반례 | ←반례대상 |
- evidence 등급 3종, 노드 frontmatter 스키마(§4) 명시. sources 포맷(`"260608 §장-절"`) 명시.
- **수용:** schema.md만 읽고 규격대로 새 노드 작성 가능. 능동/수동 중복 술어가 어휘에 없음.

### Task 2 — 소스 파싱 · 노드 추출 (`ontology/nodes/`)
- 정본 `260608`을 절(2-1~8) 단위 정독, `260528`로 보강. **헤딩이 없으므로 볼드 텍스트(`**2-1. …**`)를 절 경계로 인식**(C3).
- 노드 60~100개 작성. 예: `멜라토닌·세로토닌·수면압력·아데노신·심부체온·REM수면·NREM수면·오렉신·코르티솔·아침_산책·청색광차단·족욕·저녁식사_시간·항중력근자극·카페인·알코올·온습도·베개·매트리스·일자목·접지`.
- 저자 개인경험은 `evidence: 저자_개인경험`으로 구분(예: 미지근한 토마토 한 입, 속이 차면 각성).
- 인용 문헌(아리타 히데호·니시노 세이지·『3분 수면 혁명』·wellness101 박상민)은 `sources`에 기재. 본문 인용은 `"260608 §6-1"` 포맷(C3).
- 관계는 능동 8종만, 타깃 노드는 반드시 별도 파일로 존재.
- **수용:** S1 — 본문 2~8장 모든 절이 ≥1 노드로 표현됨(빌드 커버리지 리포트로 확인).

### Task 3 — 빌드 스크립트 (`scripts/build_index.py`)
- nodes/ 전체 frontmatter 파싱 → `index.md` 재생성.
- **역관계 생성(C2):** schema 역술어 매핑표로 각 관계의 반대 방향을 대상 노드 항목에 역링크로 추가.
- **검증 게이트 (실패 시 비정상 종료, 종료코드≠0):**
  - 관계 술어가 schema의 닫힌 어휘(8종)에 없으면 오류.
  - 존재하지 않는 노드 id를 가리키는 관계가 있으면 오류.
  - `evidence` 누락·오타 오류. `aliases` 중복(다른 노드가 같은 별칭) 오류.
  - **id 규칙 위반(정규식·파일명 불일치) 오류(C1).**
- **S1 커버리지 리포트(C3):** 2~8장 각 절(§2-1~§8)별로 인용한 노드 수를 집계해 출력. 0인 절이 있으면 경고(설정에 따라 실패).
- 순수 표준 라이브러리만 사용(외부 의존 최소화). YAML은 frontmatter 단순 파서 또는 pyyaml 1개 허용.
- **수용:** 일부러 깨진 노드(잘못된 관계어, 없는 id, 잘못된 id 형식) 주입 시 빌드가 실패한다(S7).

### Task 4 — 답변 harness (`CLAUDE.md`, ≤800단어)
규칙:
1. **인덱스 상주(C4):** 문서 상단에 `@ontology/index.md`를 import해 Tier 1 인덱스를 세션 상주시킨다. 컨텍스트 압축·세션 재시작 후에도 인덱스가 재로드됨을 규칙으로 명시.
2. **트리거:** `<channel source="telegram">` 이벤트에서 user_id 추출.
3. **개인화 로드:** `profiles/<id>.md` 먼저 읽음(없으면 빈 템플릿 생성).
4. **라우팅:** 상주 인덱스에서 질문↔별칭 매칭으로 관련 노드 id 선정 → 해당 `nodes/*.md` 2~3개만 read. 책 밖이면 추측 금지 → "이 책에서는 다루지 않아요" + 필요 시 전문의 안내.
5. **답변 형식:** 그룹 톤, **3~5문장**, 핵심 먼저, 끝에 근거 한 줄(`— 근거: 260608 §6-1 / 일반원칙` 또는 `저자 개인경험`).
6. **개인화 반영:** 프로필의 습관·시도이력·제약 적용.
7. **메모리 갱신:** 대화에서 드러난 새 사실을 profiles/<id>.md에 append (**범위: 대화 전반, D5**). 건강 민감정보는 사용자가 명시한 것만. 신규 사용자 첫 응답 시 데이터 저장 1회 고지(R4).
8. **가드레일(C6):** 아래 **차단 트리거** 발화 시 답하지 않고 전문가 권유.
   - 차단 트리거: 진단 요청("불면증인가요"), 약물·복용량("멜라토닌 몇 mg", "수면제 추천"), 질환 치료법.
   - 허용: 책에 있는 일반 수면 위생·환경·습관 조언.
   - 위기 신호(자해·극심한 고통): 공감 + 한국 자원 안내(자살예방상담 109, 정신건강위기상담 1577-0199).
- **수용:** S2·S3·S5·가드레일 통과.

### Task 5 — 텔레그램 연결 (`SETUP.md` 작성 + 사용자와 1회 셋업)
사용자 토큰이 필요해 자동화 불가. SETUP.md에 절차 명시:
```
1) @BotFather → /newbot → 토큰
2) /plugin install telegram@claude-plugins-official → /reload-plugins
3) /telegram:configure <토큰>
4) claude --channels plugin:telegram@claude-plugins-official   (상시 세션)
5) 봇 DM → 페어링코드 → /telegram:access pair <코드>
6) /telegram:access group add <그룹ID>     (@RawDataBot으로 -100… ID 확인)
7) /telegram:access set mentionPatterns '["수면봇","잘자는법","\\b수면\\b"]'
8) /telegram:access policy allowlist
```
- 기본값 `requireMention: true` 유지(단체방 소음 0). `--no-mention` 미사용.
- **D3 상시 PC**: "세션이 떠 있어야 봇이 응답한다" 명시 + PC 절전/재부팅 시 재기동 절차.
